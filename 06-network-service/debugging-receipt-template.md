# Networking Debugging Receipt

Use one receipt to preserve evidence before changing several layers at once.

| Receipt field | Observation |
|---|---|
| Symptom | |
| Exact command/request ID | |
| Client output | |
| Matching server log/trace | |
| Suspected layer: connect, frame, parse, validate, compute, respond, or load | |
| Next experiment and predicted result | |
| Result | |
| What you now think happened | |

For a bottleneck investigation, also name the metric expected to change if the
hypothesis is right. A useful receipt may document a failed hypothesis when the
experiment rules it out.
